# 03 · The agent loop — by prompt

The goal: have the agent build you a real agent — a loop that chains tool calls until a task is
done — and then review it for the one thing agents love to leave out.

## Drive

> Create `agent_loop.py` with the `anthropic` SDK. Build a minimal but real agent:
> - Two tools: `calculator` and `word_count`, each with an `input_schema`.
> - A function `agent(task, max_iterations=6)` that loops: call the model; if it returns a
>   final answer, return it; if it requests tools, run every requested tool, append the results
>   to the conversation, and loop again.
> - A hard cap on iterations so it can never loop forever.
> - Print a one-line trace of each tool call (name, input, result) so I can watch it work.
> Test it with a task that needs both tools, like: "Compute 144 / 12, then count the words in
> 'agents are just loops around a model'. Give me both answers."

Good output chains several tool calls and prints a trace, ending in a combined answer.

## Review

This is the most important review in the track. Check, in order:

- **Is there a `max_iterations` cap, and does the loop actually stop on it?** No cap means a
  confused agent runs until your token bill says stop. This is the number one thing agents
  omit. If it's missing, that alone is a fail.
- **Does it handle *all* tool blocks in a turn, not just the first?** The model can request
  several at once. A loop that runs `content[0]` only will silently drop calls.
- **What's the exit condition?** It should stop when `stop_reason` isn't `tool_use`, not after
  a fixed number of steps. The cap is a safety net, not the plan.
- **Is there a trace?** Without printed steps you can't debug a misbehaving agent. If it's
  missing, ask for it — you'll want it for every lesson after this.

Push back:

> There's no cap on the loop — add a `max_iterations` parameter and make the function return a
> clear "did not converge" message if it's hit. Also handle every tool_use block in a turn, not
> just the first one.

# 05 · Reflection — by prompt

The goal: have the agent build a self-critique loop, then review it with the senior question in
mind — not "does it work" but "is it worth what it costs."

## Drive

> Create `reflection.py` with the `anthropic` SDK implementing the evaluator-optimizer pattern:
> - A `generate` step that produces an answer to a task.
> - A `critique` step (same model, different system prompt) that scores the draft 1–10 on a
>   fixed first line like `SCORE: <n>` and gives bullet feedback.
> - A loop that regenerates with the feedback until the score clears a threshold or it hits a
>   max number of rounds.
> - Track and print the total tokens used across all passes.
> Test with: "Explain what an agent loop is to a DevOps engineer, in 3 sentences, with one
> analogy."

Good output shows a first draft, a score with feedback, a revised draft, and a total token
count at the end.

## Review

- **Is the total token cost printed?** This is the whole point of the lesson. Reflection trades
  tokens and latency for quality, and you can't judge the trade if you can't see the bill. If
  it's missing, demand it.
- **Is the critic's score in a parseable format?** It should reliably extract a number (e.g.
  regex on `SCORE:`). Free-form self-assessment can't drive a loop.
- **Is there a `max_rounds` cap?** Same lesson as the agent loop: nothing should be able to
  polish forever.
- **Now weigh it.** Run it once. Was the revised answer meaningfully better than the first, and
  by how many tokens? Sometimes reflection earns its cost; often it doesn't. Forming that
  judgment is the skill.

Push back:

> Add up and print the total tokens across every generate and critique call, and make the critic
> always start its reply with `SCORE: <n>` so the number is parseable.

# 07 · Tracing — by prompt

The goal: direct the agent to make your agent observable, then review the trace the way you'd
review any service's logging — because this is your home turf.

## Drive

> Add structured tracing to an agent loop in `tracing.py` (anthropic SDK). For every step, emit
> one JSON line (one event per line) capturing: step number, whether it was a model call or a
> tool call, the tool name and input/result, input and output tokens, an estimated cost in USD
> from a per-token price, and the latency in ms. At the end, print a summary with total model
> calls, total cost, and total latency. Keep the events greppable and jq-friendly.

Good output is a stream of one-line JSON events plus a summary, the kind of thing you could pipe
straight into a log pipeline.

## Review

You review logging for a living, so apply the same eye:

- **Is cost attributed per call and summed?** A multi-step agent's cost compounds. The summary
  is where you'd catch a quietly expensive run. Confirm it's there and the math is right.
- **Is latency captured per model call?** That's the number that threatens an SLO.
- **One structured line per event?** Multi-line or pretty-printed JSON breaks `grep` and `jq`.
  It should be one compact line per event.
- **Is anything sensitive being logged?** Tool inputs can contain user data. In real life you'd
  redact. Note where that redaction would go.
- **Is the price obviously a placeholder?** Rates drift. The point is per-step attribution, not
  the exact number — but make sure it's easy to update.

Push back:

> The events are pretty-printed across multiple lines, which breaks jq. Emit one compact JSON
> object per line, and add a `run_id` to every event so I can correlate a single run.

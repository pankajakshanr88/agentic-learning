# 02 · Giving the model hands — by prompt

The goal: get tool use working by directing the agent, then review the handshake it builds,
because that handshake is the foundation of everything later.

## Drive

> In a new file `first_tool.py`, using the `anthropic` Python SDK, show a single tool call
> end to end:
> 1. Define one tool, `calculator`, with a proper `input_schema` (an `expression` string).
> 2. Implement the calculator in Python.
> 3. Send a message like "What is 23 * 47 + 1? Use the calculator." with the tool available.
> 4. Detect the `tool_use` response, print the exact tool name and input the model requested,
>    run the calculator yourself, send the result back as a `tool_result`, and print the
>    model's final answer.
> Keep it to a single tool call — no loop yet. Comment the four steps.

Good output prints the model's request (so you can see the JSON it sent), the computed result,
and a final answer that uses it.

## Review

- **Who runs the tool?** Confirm *your code* executes the calculator. The model only returns a
  request. If the agent wrote something that lets the model "run" code directly, that's wrong
  and dangerous.
- **Is the `tool_result` linked by `tool_use_id`?** That id ties your result to the model's
  request. Missing it works with one tool and breaks with several.
- **Does the conversation get both messages appended** — the model's request *and* your result
  — before the final call? A common agent mistake is dropping one.
- **The calculator probably uses `eval`.** Fine for a toy. Note it now; lesson 09 is where you
  make it safe. Don't ship `eval` on untrusted input.

Push back if needed:

> You're calling the model's tool request directly instead of having our own code run the
> calculator and return a `tool_result`. Fix the flow so our code executes the tool.

# 04 · ReAct — by prompt

The goal: direct the agent to build a multi-tool agent that reasons before it acts, then review
the one behavior that separates a useful agent from a confident liar.

## Drive

> Create `react_agent.py` with the `anthropic` SDK, building on a standard agent loop:
> - Three tools: `kb_lookup` (reads from a small hardcoded dict of infra facts like
>   `server_count`, `cost_per_server_monthly`, `region`), `calculator`, and `current_time_utc`.
> - A system prompt that tells the model to think briefly about which tool it needs, use tools
>   for real numbers, and never guess.
> - Print both the model's reasoning (text blocks) and each tool call, so I can see it plan.
> Test with: "What's our total monthly server cost, and what time is it in UTC right now?"

Good output shows the model reasoning, looking up two facts, multiplying them, checking the
clock, and answering.

## Review

- **Does the system prompt forbid guessing?** This is load-bearing. Without "use tools, don't
  guess," the model will invent a plausible number instead of looking it up. Confirm it's there.
- **Now test the failure case yourself.** Ask it something none of the tools can answer. It
  should say it can't, *not* fabricate a number. If it makes one up, you've just watched a
  hallucination — and that's exactly what evals (lesson 08) exist to catch.
- **Are the tool descriptions clear?** The model picks tools by reading them. Vague descriptions
  cause wrong choices. Read them as if you were the model.
- **Does it actually print reasoning?** That trace is your debugging lifeline when the plan goes
  wrong.

Push back:

> The agent invented a cost instead of using `kb_lookup`. Strengthen the system prompt to forbid
> guessing and require a tool lookup for any number, and show me the reasoning text each step.

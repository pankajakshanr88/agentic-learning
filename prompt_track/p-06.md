# 06 · Framework vs. by hand — by prompt

The goal: have the agent rebuild your agent with the Claude Agent SDK, then review what the
framework took off your plate and — more importantly — what it now hides from you.

## Drive

> Rewrite the multi-tool agent from lesson 04 using the Claude Agent SDK (`claude-agent-sdk`)
> instead of a hand-written loop. Define the tools as decorated functions, create an `Agent`
> with a system prompt and the tools, and run a task through it. Keep it minimal. If the SDK
> isn't installed, print clear install instructions and exit cleanly rather than crashing.

Good output is much shorter than lesson 04 — the loop, the `stop_reason` check, and the
tool-result plumbing are all gone, handled by the SDK.

## Review

- **Open lesson 04's code next to this.** List what the framework now does for you: the loop,
  tool dispatch, message history, schema generation from function signatures.
- **Then list what it hides.** Where's the iteration cap now? Can you see the per-step trace?
  Can you intercept a tool call to validate it? If you can't answer, that's the cost of the
  abstraction — note it.
- **Does it fail gracefully without the SDK installed?** A missing dependency should print
  instructions, not a stack trace.
- **The senior call:** for something you'd put on call, can you still get at the loop when it
  misbehaves? If the framework won't let you, that's a real reason to stay closer to the metal
  for that piece.

Push back:

> Where does this enforce a max-iteration cap and how would I trace each step? Show me how to
> add a per-step log and a hard cap using the SDK, or explain what it doesn't expose.

## Understand

You can only judge a framework because you built the loop by hand first. That's the whole point
of the ordering. Deep dive: [06 · Framework (SDK)](../pages/d2-06.html).

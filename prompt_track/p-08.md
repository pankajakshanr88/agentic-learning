# 08 · Evals — by prompt

The goal: have the agent build an eval suite that gates a deploy, then review it like the CI gate
it's meant to be. This is the lesson that maps most directly onto a job.

## Drive

> Create `eval_harness.py` (anthropic SDK) that tests a prompt for regressions, like a test
> suite for non-deterministic output:
> - A small system-under-test (a prompt + a function that calls the model).
> - An `EVAL_SET` of cases, each with an input and a way to grade it. Support three grading
>   styles: substring `contains`, a rule (regex/number), and `LLM-as-judge` (a model grades an
>   open-ended answer PASS/FAIL against a rubric).
> - Compute an overall pass rate, compare to a threshold, and `sys.exit(1)` if it's below — so
>   it works as a CI gate.
> Print a per-case PASS/FAIL line and the final score.

Good output runs the cases, prints pass/fail per case and a score, and exits non-zero when the
score is too low.

## Review

- **Does it exit non-zero on failure?** This is the entire integration story. `python
  eval_harness.py && deploy` is the gate. If it always exits 0, it's not a gate, it's theater.
- **Prove it.** Change the system prompt to something wrong ("answer only in French") and re-run.
  Cases should fail and the exit code should flip. If it doesn't, the grading is broken.
- **Is the LLM-judge rubric specific?** A vague rubric gives a vague grader. It should describe
  exactly what "pass" means for that case.
- **Is the right grader used per case?** Don't burn an LLM-judge call on something `contains`
  would check for free. Cheapest method that catches the real failures.

Push back:

> Make `main()` exit with code 1 when the pass rate is below the threshold, and show me it works
> by adding a deliberately failing case. Tighten the judge rubric so it's not just "is this good."

## Understand

Evals are tests where "pass" means "good enough," wired into CI. This is the hireable skill.

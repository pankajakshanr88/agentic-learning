# 01 · Hello, LLM — by prompt

The goal: get a feel for the model as a stateless function, without typing the SDK calls
yourself. You'll have the agent write a tiny script, then you'll prove the point by reading it.

## Drive

Paste this into Cursor or Windsurf (agent mode):

> Create `hello_llm.py` using the official `anthropic` Python SDK. It should:
> 1. Load `ANTHROPIC_API_KEY` from a `.env` file with python-dotenv, and exit with a clear
>    message if it's missing.
> 2. Define a function `ask(messages, system=None)` that makes one `client.messages.create`
>    call and returns the text plus the token usage.
> 3. In `main()`, make one call asking "In one sentence, what is an LLM?", print the reply and
>    the input/output token counts.
> 4. Then make a *second, separate* call asking "What did I just ask you?" — without sending
>    the first exchange — to demonstrate the model has no memory between calls.
> Add brief comments explaining the three message roles. Don't add extra features.

Good output is a short file that runs and prints two replies, where the second one admits it
doesn't know what you asked. If it runs, you've driven the agent successfully.

## Review

Now the part that matters. Read what it wrote and check:

- **Did it actually make two separate calls?** A sneaky agent might keep the history and "pass"
  the test wrongly. The second call's `messages` should *not* contain the first exchange.
- **Is the key checked before use?** There should be a clear failure if `ANTHROPIC_API_KEY`
  is missing, not a stack trace.
- **Does it report token usage?** If it skipped that, you can't see your cost.
- **Did it sneak in extras** you didn't ask for — retries, streaming, a CLI? More surface area
  to understand and maintain. Ask why, or have it removed.

If anything's off, push back:

> The second call still includes the first exchange in `messages`. Remove that so it genuinely
> has no history, and add a comment explaining why the model can't remember.

## Understand

The thing to internalize: the model has no memory, and "remembering" is just resending the
transcript. If you want the line-by-line version of why, read the code-track deep dive:

# 04 · ReAct: reasoning and acting

You've built the loop. Now watch a model use it to solve a problem you didn't spell out the
steps for. You ask "what's our monthly server cost and what time is it?" and it figures out, on
its own, that it needs to look up two facts, do some arithmetic, and check a clock — in that
order. That pattern of reasoning between actions has a name: ReAct.

By the end you'll see the agent narrate its thinking and chain three different tools to answer
an open-ended question.

## The one idea

ReAct means "reason, then act," repeated. It is not a new mechanism. It's the lesson 03 loop
with two changes:

1. Several tools, so the model has to *choose* which one fits each step.
2. A nudge to think out loud before acting, which makes its choices better.

That's the whole upgrade. Same loop, more tools, a bit of prompting.

## Reading the code

We give it three tools now — a fake knowledge base, a calculator, and a clock — so it has real
choices to make.

```python
KB = {"server_count": 42, "cost_per_server_monthly": 30, "region": "us-east-1"}

def run_tool(name, args):
    if name == "kb_lookup":
        return KB.get(args["key"], f"no such key: {args['key']}")
    if name == "calculator":
        return eval(args["expression"], {"__builtins__": {}}, {})
    if name == "current_time_utc":
        return datetime.now(timezone.utc).isoformat(timespec="seconds")
    return f"unknown tool: {name}"
```

The system prompt is doing real work here. It tells the model to use tools for real numbers and
never guess. That one instruction is the difference between an agent that looks things up and
one that makes them up.

```python
SYSTEM = (
    "You are an infrastructure assistant. Think briefly about which tool you need, then "
    "use tools to get real numbers — never guess. When you have enough, give a final answer."
)
```

The loop is the one you already know, with one addition: we print the model's `text` blocks,
which is the reasoning it does before each action.

```python
for block in resp.content:
    if block.type == "text" and block.text.strip():
        print(f"  [step {step}] thinking: {block.text.strip()}")

if resp.stop_reason != "tool_use":
    return resp.content[-1].text if resp.content[-1].type == "text" else "(done)"
```

When you run it, the trace reads like a worklog: *think* ("I need the server count and the
per-server cost"), *act* (`kb_lookup`), *act* (`kb_lookup` again), *act* (`calculator`), *act*
(`current_time_utc`), then a final answer. The model planned that sequence; you just ran the
tools.

## What to watch for

- Tool choice is driven by the descriptions. Vague descriptions lead to wrong choices — they're
  prompt engineering, so write them like API docs.
- "Never guess" in the system prompt is load-bearing. Without it, the model is happy to invent a
  plausible-looking number, which is a hallucination (lesson 08 is about catching those).
- The reasoning text is genuinely useful for debugging. When the agent goes sideways, the
  "thinking" lines usually show you where its plan went wrong.

## Recap

- ReAct is the same loop plus multiple tools plus reason-before-act.
- The model picks tools based on their descriptions, so descriptions matter.
- A system prompt that says "use tools, don't guess" is what keeps it honest.
- Printing the reasoning turns the agent from a black box into something you can follow.

# 06 · By hand vs. a framework

You've now written the agent loop three times. Frameworks exist so you don't have to. This
lesson rebuilds the same agent using the Claude Agent SDK, and the point isn't the SDK — it's
the comparison. Because you know what the loop does, you can see exactly what the framework
hands you and, more importantly, what it hides. That second part is what saves you at 2am when
something breaks.

By the end you'll have the same multi-tool agent in about a third of the code, and a clear sense
of the trade.

## Setup for this one lesson

This is the only lesson with an extra dependency. Uncomment `claude-agent-sdk` in
`requirements.txt`, then `pip install -r requirements.txt` again. If you skip it, the file
prints install instructions and exits cleanly, so it won't derail your weekend.

## The one idea

A framework manages the loop, tool dispatch, message history, and retries — all the plumbing you
wrote by hand. You write less. You also see less. Hidden control is fine right up until you need
to reach in and change it.

## Reading the code

With the SDK, a tool is just a decorated function. The SDK reads the signature and docstring to
build the schema you used to write out by hand in lessons 02 through 04.

```python
@tool
def calculator(expression: str) -> float:
    """Evaluate a basic arithmetic expression."""
    return eval(expression, {"__builtins__": {}}, {})

@tool
def kb_lookup(key: str) -> str:
    """Look up an infra fact. Keys: server_count, cost_per_server_monthly."""
    return {"server_count": 42, "cost_per_server_monthly": 30}.get(key, "unknown key")
```

And the agent is three lines. Compare this to lesson 04: the loop, the `stop_reason` check, the
appending of tool results, the iteration cap — all of it is gone, because the SDK does it.

```python
agent = Agent(
    model=os.getenv("ANTHROPIC_MODEL", "claude-sonnet-4-6"),
    system="You are an infra assistant. Use tools for real numbers; never guess.",
    tools=[calculator, kb_lookup],
)
result = agent.run("What's our total monthly server cost?")
```

That `agent.run(...)` is the entire lesson-03 loop, collapsed. Convenient. Also opaque: when it
misbehaves, you can't see the steps unless the framework chooses to show you.

## What to watch for

- The SDK's API can change between versions. If a call here doesn't match the current docs, the
  docs win — and adapting it is good practice.
- Less code is not automatically better. You traded visibility for brevity. For a quick build,
  great. For something you operate, make sure you can still get at the loop.
- You can only really judge the framework *because* you built the loop first. That's why the
  course did it the hard way before showing you the easy way.

## Recap

- A framework removes the boilerplate loop and infers tool schemas for you.
- You write roughly a third of the code and give up some visibility.
- Knowing what's hidden is the advantage you have over someone who only ever used the framework.
- Choose DIY or framework on purpose, per project, not by default.

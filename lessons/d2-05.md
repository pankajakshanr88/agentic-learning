# 05 · Reflection: the agent grades its own work

Here's a cheap trick that often buys real quality: after the model produces an answer, ask it
(or another model) to critique that answer, then revise. It's the same move as a code review or
a lint-then-fix loop. It also costs more tokens and more time, so part of this lesson is
learning to see that trade-off, not just the upside.

By the end you'll watch a first draft get scored, criticized, and rewritten — and you'll see
the token bill for the privilege.

## The one idea

The pattern is called evaluator-optimizer:

1. A generator produces an answer.
2. An evaluator — the same model with a different prompt — scores it against criteria.
3. If the score is too low, feed the critique back and regenerate. Repeat until it passes or you
   hit a cap.

More passes, higher quality, higher cost. Whether it's worth it is a measurement question, and
lesson 08 is how you'd actually measure it.

## Reading the code

One helper wraps a call and keeps a running token total, because the cost is the point.

```python
total_tokens = 0

def call(system, messages, max_tokens=600):
    global total_tokens
    resp = client.messages.create(model=MODEL, max_tokens=max_tokens, system=system, messages=messages)
    total_tokens += resp.usage.input_tokens + resp.usage.output_tokens
    return resp.content[0].text
```

The generator writes (or rewrites, if given feedback). The critic scores. Notice the critic is
told to answer in a fixed format — `SCORE: <n>` on the first line — so we can parse a number out
of it reliably.

```python
def critique(task, draft):
    system = (
        "You are a strict reviewer. Score the draft 1-10 for correctness, clarity, and "
        "completeness. Reply EXACTLY as: 'SCORE: <n>' on the first line, then bullet feedback."
    )
    out = call(system, [{"role": "user", "content": f"TASK:\n{task}\n\nDRAFT:\n{draft}"}])
    m = re.search(r"SCORE:\s*(\d+)", out)
    score = int(m.group(1)) if m else 0
    return score, out
```

The loop ties it together: draft, critique, and either pass or revise. The `threshold` is your
quality bar; `max_rounds` stops it from polishing forever.

```python
def reflective_agent(task, threshold=8, max_rounds=3):
    draft = generate(task)
    for rnd in range(1, max_rounds + 1):
        score, feedback = critique(task, draft)
        if score >= threshold:
            return draft
        draft = generate(task, feedback)
    return draft
```

At the end it prints the total tokens across every pass. That number is the price of reflection,
and it's there on purpose so you feel it.

## What to watch for

- Reflection is not free. Each round is at least two extra model calls. On a hot path, that
  latency and cost add up fast.
- Forcing the critic into a fixed output format (`SCORE: n`) is what makes it parseable. Free-form
  self-assessment is hard to act on programmatically.
- A model grading itself is useful but not gospel. For anything that matters, deterministic
  criteria beat a vibe score — which is the thread that leads straight into evals.

## Recap

- Reflection = generate, critique, revise, until good enough or capped.
- It trades tokens and latency for quality; measure whether that trade is worth it.
- Constrain the critic's output format so you can parse and act on it.
- Self-critique is a stepping stone to real evals (lesson 08).
